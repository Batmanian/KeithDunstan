# AI Agent Instructions — Keith Dunstan Archive

This file helps AI coding assistants be immediately productive in the Keith Dunstan digital archive project.

## Project Overview
Digital archive of Australian journalist Keith Dunstan (1925–2013), built with Eleventy (11ty) + Bootstrap 5 + Gulp. Site: https://keithdunstan.org. Content: memoirs, articles from The Bulletin (under pseudonym "Batman"), Walkabout magazine.

## Content authority: the vault, not src/

Every book chapter and article is authored in `vault/` — a git submodule
(github.com/JackDunstan/KD-Vault) that is an Obsidian-compatible vault and
the single source of truth for that content. `src/books/[book-slug]/*.md`
and `src/articles/[publication-slug]/*.md` are **symlinks** into `vault/`,
generated by `scripts/link-vault-content.js` (`npm run link:vault`) —
Eleventy reads them exactly as it would a real file.

**Never create or edit a chapter/article `.md` file directly under
`src/books/` or `src/articles/`.** Add or edit it in `vault/` instead (an
existing file's symlink means the edit is live immediately; a new file
needs `npm run link:vault` afterward to create its symlink). A fresh clone
needs `git clone --recurse-submodules` or `git submodule update --init`,
or `src/books/`/`src/articles/`/`src/img/` will be full of dangling
symlinks and the build will be missing all content.

The topics list (`src/_data/topics.md`) and book/publication cover
images (`src/img/*.jpg` for the ones with real covers) are symlinks into
`vault/` too, for the same reason. Directory-level Eleventy config
(`books.json`, `articles.json`, per-book `[book-slug].json`) and non-content
assets (raw scan `.HEIC` files, stray images) are **not** vault content and
stay as real files directly in `src/`.

See `CLAUDE.md`'s "Content authority" section for the full picture,
including the one hardcoded special case (Ratbags' chapters are read by
Eleventy as `.njk`, not `.md`).

## Essential Workflows

### Build & Development
- **Local dev**: `npm run watch` (outputs to `dev/`, browser-sync enabled)
- **Production build**: `npm run build` (outputs to `docs/`, minified, optimized)
- **Deploy**: `git push` to `master` triggers Netlify build from `docs/`
- **Never edit**: `dev/`, `docs/` — these are build outputs

### Content Management
- **Articles**: Add to `vault/articles/bulletin/` or `vault/articles/walkabout-magazine/` (not `src/`), then `npm run link:vault`
- **Books**: Add chapters to `vault/books/[book-slug]/` (e.g., `no-brains-at-all/`), then `npm run link:vault`
- **Trove ingestion**: Use Python scripts in `trove/` → review output → move to `vault/articles/[publication-slug]/` → `npm run link:vault` (see `trove/README.md`)
- **OCR processing**: Use `ocr/transcribe.js` for scanned documents → manual correction required → write the result into `vault/books/[book-slug]/`

## Key Conventions
- **Frontmatter**: Every `.md` file needs `title`, `date`, `summary`. Articles add `categories` and `tags` (5–15 granular proper nouns only).
- **Language**: Australian English, single-quote dialogue.
- **Tags**: Proper nouns (people, places, organizations) — no descriptive labels.
- **File naming**: Book chapters prefixed with numbers (e.g., `1-chapter-title.md`).

## Pitfalls to Avoid
- Committing `.env` (Trove API key) — it's gitignored.
- Empty `tags: []` in articles — breaks tag filtering.
- OCR errors in fetched content — always review and correct.
- Changing build output directories — breaks Gulp/Netlify pipeline.
